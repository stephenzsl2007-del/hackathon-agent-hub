# 息屿：原生桌面能力

项目上级目录中的 `息屿.app` 是可直接双击运行的 macOS Apple Silicon 应用。开发时也可以双击 `start.command`；它优先使用已安装的 Electron 运行当前源码。打包命令 `node desktop/package.cjs` 会更新上级目录的应用。

## 桌面入口

默认打开真正透明、无边框、无窗口阴影的原生窗口。舞台默认使用所在显示器工作区约 72% 宽、64% 高，并靠右下放置。页面和场景的透明度由渲染层保持；原生窗口不使用壁纸截图。

原生产品始终保持透明桌面形态，不提供传统完整窗口的切换入口。

系统菜单栏的像素幼苗图标提供完整操作，场景右键菜单使用同一组操作：

| 操作 | 入口 |
| --- | --- |
| 显示／隐藏花园 | 托盘菜单；显示不会主动获取输入焦点 |
| 置顶开关 | 托盘「保持置顶」 |
| 交互模式／完全穿透 | 托盘相应选项 |
| 从完全穿透中找回 | `⌘⌥⇧G`，或托盘「找回花园与工具」 |
| 文件投喂模式 | `⌘⌥⇧F`，或托盘「进入文件投喂模式」 |
| 移动 | 托盘「移动花园」，或位置子菜单的方向操作 |
| 缩放／恢复位置 | 托盘「调整位置与大小」 |
| 结束投喂／移动 | `Escape`，或再次选择同一托盘操作 |
| 完全退出 | 托盘「完全退出息屿」，或 `⌘Q` |

托盘和场景右键菜单还可以切换白天／夜色、环境音、麦克风送风，以及启动独立的五阶段成长演示。Windows 对应组合为 `Ctrl+Alt+Shift+G/F`；macOS 使用额外的 Option 键，避免占用 Finder 的 `⌘⇧G`。

交互模式由渲染层命中测试请求原生 `setIgnoreMouseEvents(..., { forward: true })` 切换透明区域穿透；CSS `pointer-events` 不承担系统穿透。完全穿透是可靠退路，不接受场景点击，但保留托盘和全局恢复快捷键。投喂模式会临时关闭穿透并置顶，结束后恢复用户的置顶和鼠标模式设置。

位置、尺寸、置顶、鼠标模式在停止变化 500 毫秒后保存。显示器移除、连接或工作区变化后会重新约束边界，避免花园留在不可见屏幕。代码具备此处理，但物理多显示器插拔仍需现场验证。

## 文件回收边界

原生 preload 只接收用户拖入的真实 `File`，用 Electron `webUtils.getPathForFile` 取得路径。页面不能传入任意路径调用回收。

`prepareFiles(files)` 返回有效期 5 分钟的批次与逐项清单，不移动文件。界面展示清单后，用户确认才调用 `confirmTrash(batchId)`。原生端再次核对文件设备、inode、大小、修改时间及真实路径，然后调用系统 `shell.trashItem`。只在成功后返回 1 份饲料奖励；大小不影响奖励。重复批次、并行重复确认、失败项、取消项均不会重复奖励。

首版只接受普通可写文件。文件夹、应用、符号链接、系统目录、用户 Library、废纸篓、应用本身与存档目录都会拒绝。不会扫描未被选择的文件，也不会读取文件正文。

`openTrash()` 打开系统废纸篓。没有提供未经验证的直接恢复按钮；用户可以使用系统自己的恢复操作。

## 统一存档

原生主进程是磁盘存档的唯一写入方。文件位于 Electron 的 `app.getPath('userData')`：

- `garden-state.json`：日常花园、动物、资源、专注与用户设置快照。
- `demo-state.json`：独立演示快照，使用 `slot: 'demo'` 访问。
- `window-state.json`：原生窗口位置和模式。

`loadState()` 返回状态、版本与最后保存时间。`saveState(snapshot)` 合并 500 毫秒内的请求，完成临时文件写入、同步和原子替换后，才返回 `{ ok: true, revision, savedAt }`。保存失败保留原文件并返回明确错误。最近一次有效版本保存在 `.bak`；主文件损坏时尝试备份，同时保留损坏文件。

正常退出先向渲染层发送带请求 ID 的 `prepare-quit` 命令。渲染层完成最终保存后用 `ackQuit(requestId)` 确认；主进程随后刷新所有待写入状态再退出。渲染层无响应时最多等待 3 秒，然后刷新已经收到的状态并正常退出，不强杀进程。

不接收媒体数据作为功能输入，不持久化麦克风原始音频或键盘内容。当前架构仍是单个渲染窗口负责游戏规则、主进程负责受控持久化，并未声称已经实现架构文档中计划的 utilityProcess 世界服务。

## 权限和联机

麦克风仅允许本机应用页面申请音频权限，不开放摄像头权限；打包的 Info.plist 包含用途说明。锁屏／休眠向渲染层发送 suspend 命令，由音频模块释放采集。全局快捷键只用于找回和投喂；没有实现全局键盘内容监听。键盘雨的范围须由界面明确标注为应用内。

桌面本地服务默认使用端口 4178，网页开发服务使用 4177。手机连接同一 Wi-Fi 后可扫描邀请二维码，用触控控制六种环境互动。手机不会获得文件、存档、窗口权限，也不需要麦克风权限。

## 已运行的定向验证

- `node --test tests/native-services.test.cjs`：存档合并与恢复、写入失败保留旧数据、取消回收、确认前文件变化、符号链接及保护目录拒绝、原生操作失败、重复确认零重复奖励；退出握手等待、错误请求 ID 拒绝和无响应超时。
- `tests/verify-native-trash.cjs`：用 Electron `shell.trashItem` 处理专门创建的可丢弃测试文件；确认原路径消失，真实 `~/.Trash` 中的文件存在、大小和内容一致，重复请求奖励为 0。实际结果保存在 `tests/native-trash-verification.json`。

透明画面、真实桌面穿透、托盘操作、麦克风实体输入与显示器热插拔属于原生 UI／设备验收，不能用以上文件测试替代。以项目最终验收记录为准。
