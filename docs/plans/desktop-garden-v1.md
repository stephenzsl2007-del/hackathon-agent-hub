# 桌面花园创意计划 v1：桌面野生

日期：2026-10-18
状态：供团队讨论的概念与范围计划；尚未实现或实机验证。
项目名：**桌面野生**（暂定，可更名）。
协作仓库：https://github.com/stephenzsl2007-del/hackathon-agent-hub

## 1. 这次要做什么

做一个常驻电脑桌面的微型花园：用户的声音、键鼠动作和停顿成为花园里的风、雨与生长条件；用户可以主动整理、演奏和分享它，也可以让它安静陪伴工作。

一句话：**把你与电脑相处的动作，变成一座可以触碰、可以演奏、会记住你的花园。**

用户已经明确的方向：

- 面向电脑桌面交互，突出“沉浸”；延续“平行桌面”的空间感。
- 不做闯关、任务、积分驱动的游戏；丰富的是可探索、可创作的交互。
- 重点利用麦克风、键盘、鼠标，其他设备按体验价值逐步加入。
- 当前先形成想法计划，后续代码与协作在本仓库进行。

本文中的产品名、技术路线、优先级和里程碑均为本版建议，不表示团队已经确认或功能已经完成。

## 2. 核心差异：让交互留下结果

一次动作既有即时反馈，也能改变后续体验：

> 敲杯子三下 → 长出三朵铃铛花 → 用鼠标调整位置 → 吹气带动花朵 → 花园按空间顺序响起 → 保存为自己的小花圃。

所有输入围绕同一组植物、土壤、水和风发生作用，不能各做各的独立动画。风要能同时影响枝叶、花粉和水面；植物的位置要能改变演奏顺序；传播出去的种子要保留母株的一些特征。

三项体验原则：

1. **动作看得懂**：用户能解释“刚刚为什么发生这个变化”。
2. **变化留得住**：新植物、布局和用户保存的声景可以恢复。
3. **随时放得下**：没有签到、枯死惩罚或必须完成的日常任务。

## 3. 花园怎样住在桌面上

首版建议为屏幕边缘的一条花圃，主动展开后进入更大的造园空间。先采用轻量二维或 2.5D 视觉，重点做植物的弹性、层次、声音和反馈，不把完整三维房间设为前提。

### A. 陪伴模式

- 花园收在用户指定的屏幕边缘，可选择始终可见或随时收起。
- 背景键盘节奏产生低强度雨滴或萤火；强度有上限，音效默认静音。
- 鼠标经过花园附近时只产生很轻的草浪，不让整屏持续追随鼠标。
- 麦克风和摄像头默认关闭；植物不会因为没人照顾而死亡。
- 覆盖层不拦截用户正常点击与输入，提供明确的暂停、收起和退出入口。

### B. 造园模式

- 用户主动展开花园，拖放植物、拨水、塑风、试声音、保存布局。
- 只有花园获得焦点后，按键才作为乐器输入。
- 模式切换要明显；退出后立即恢复普通桌面操作。

### C. 短时采样

- “种一段声音”“吹风”“借一束颜色”等动作都由用户主动开启。
- 当前使用的设备与停止入口保持可见；采样结束就关闭相应输入。
- 不依赖一直开启麦克风或摄像头来维持花园。

## 4. 交互设计：七组可以互相组合的机制

### 4.1 声音种子：让身边的声音变成植物

**动作**：选一块土，开启约 3 秒采样，哼唱、敲杯子、拍手或揉纸。

**反馈**：先出现与声音同步的幼芽轮廓，采样结束后稳定成植物。先选“铃铛花”或“蒲公英”等植物模板，再让声音改变参数。

建议的参数映射：

| 声音特征 | 植物表现 | 设计约束 |
| --- | --- | --- |
| 清楚的起音次数与间隔 | 花朵数量与排列节奏 | 去重、设数量上限；噪声不能生成几百朵花 |
| 音量包络 | 花朵开合、枝条粗细 | 归一化并限制范围，不鼓励大声喊叫 |
| 声音的明亮程度 | 花色、透明度与材质变化 | 属于艺术映射，不解释成情绪判断 |
| 稳定哼唱的音高轮廓 | 枝条弧度或演奏音阶 | 需要额外验证音高检测；不稳定时退回节奏映射 |

**留下什么**：植物保存生成种子、形态参数与简化节奏。碰触它时用合成音重现节奏，默认不保存原始声音或谈话。

**可组合**：同一段节奏可以培育不同花形；不同人依次采样，可以共同种出一排声音标本。

开源借鉴：Meyda 的音频特征提取；Patatap 的短动作、短声音与视觉反馈配对。两者都不等于现成的“识别杯子、纸张和吹气”的分类器。

### 4.2 风是公共工具：吹气、鼠标共同驱动一个风场

**动作**：开启吹风工具，短暂校准背景噪声；麦克风特征控制力度，鼠标位置或拖动方向控制风向。鼠标单独拖动也能完成同样操作。

**反馈**：微风压弯草叶，中等风吹响铃铛花，持续风把蒲公英种子送到别的土壤。快速画圈可以卷起局部小旋风。

**留下什么**：种子落入可种植区域后长出新芽，并继承母株的部分颜色或节奏；落在无效区域的种子消散，不无限增殖。

**惊喜细节**：有一滴水停在叶尖，先让叶片弯下，再借一阵风让水滴落到另一株花上。

开源借鉴：WebGL Fluid Simulation 的指针注入、流动与涡旋反馈。首版允许用简化二维向量场实现；屏幕上的流体画面本身不直接等于植物受力或真实空气模拟。

### 4.3 键盘天气：工作与停顿都能改变花园

**动作**：用户明确启用后，后台只汇总短时间窗内的键盘活动次数与间隔。

**反馈**：零散输入是露滴，连续输入是细雨，停止输入后雨缓缓收住；安静片刻后出现萤火虫或一朵慢慢展开的花。

**留下什么**：雨可以缓慢改变土壤湿润程度和小水洼；恢复后自然趋于平衡。花园不会因为没打字而变差。

**个性化**：用户选择“雨”“萤火”“叶影”三类映射中的一种；首版只做雨。

输入适配层即刻丢弃键值、扫描码和按键顺序，只向花园发送聚合强度；不存原始按键事件、输入内容或细粒度时间序列。

开源借鉴：BongoCat 对真实电脑键鼠活动的及时反馈。网页内键盘监听不能证明跨应用后台监听已经实现。

### 4.4 会演奏的花园：排列植物，就是编辑音乐

**动作**：在造园模式里移动铃铛花，画一条经过它们的风路，然后点击播放。

**反馈**：一阵风沿路径移动，碰到花朵时触发声音；位置影响触发先后，植物的声音参数影响音色与音高。

**留下什么**：保存植物布局和风路，成为一段可以再次播放的“花园乐句”。

**扩展**：明确进入演奏模式后，键盘三排分别控制叶片、露滴与花朵；按住空格托住水珠，松开时让它们落下。提供音量上限、停止和静音。

开源借鉴：Patatap 的键盘音画反馈，以及 Tone.js 的声音调度思路；首版无需导入原项目声音素材，使用原创或合成音色。

### 4.5 植物有不同的触感和行为

| 植物 | 可交互特征 | 与其他机制的组合 |
| --- | --- | --- |
| 铃铛花 | 被碰触或被风经过时响起 | 声音种子、风路演奏；首版实现 |
| 蒲公英 | 风达到门槛时散出种子 | 吹气、传播与新芽；首版实现 |
| 含羞草 | 鼠标轻触后卷起，安静一会再展开 | 提供短暂触摸体验；后续扩展 |
| 苔藓 | 在湿润痕迹附近慢慢出现 | 键盘落雨、露水滑动；后续扩展 |
| 风铃藤 | 拖动可拉弯，松手回弹 | 连接花盆、调整音色；后续扩展 |

丰富度来自行为差异和相互作用，首版先把两种植物做细。用户可以拔起、移动和撤销种植；植物数量达到上限时明确提示，避免不可控堆积。

开源借鉴：EZ-Tree 的“随机种子 + 可调参数”生成思路。它是三维树木生成项目，不能直接当成完整的花卉、传粉与生长系统。

### 4.6 从现实借东西：颜色与手势

**借颜色**：用户主动开启摄像头，将杯子、衣袖或纸张放进取色框，确认取样后关闭镜头。新花使用选定颜色；也提供图片拖入或手动选色。

**伸手进去**：可选的后续模式只先验证两种手势：捏合拿起种子、松开种下；张开手掌聚集一小群萤火虫。

**组合**：敲杯子的节奏决定花的声音，杯身的颜色决定花色，同一个现实物品在花园里有了自己的对应物。

技术参考：MediaPipe Hand Landmarker 的手部关键点。摄像头取色不需要手势模型；手势识别应单独评估性能和稳定性，并始终提供鼠标等价操作。

### 4.7 微气候瓶：保存和交换一小块花园

**动作**：圈选几株花与一条风路，点击“装进瓶子”。

**反馈**：出现一个小瓶预览，包含植物颜色、布局和一段合成声景；命名如“周日下午的三下杯声”。

**留下什么**：本地保存植物参数、布局、声音参数、风路与版本号，重新打开可恢复；后续可导出种子文件或小卡片。

**协作扩展**：朋友导入后继续种植，再发回一份新版本。首版不需要账户、在线房间、聊天或实时同步。

## 5. 为什么这些组合足够丰富

| 一次完整体验 | 用户如何参与 | 得到的结果 |
| --- | --- | --- |
| 声音标本馆 | 收集杯声、哼唱、纸声，分别种植 | 可触摸、可听的个人收藏 |
| 花园乐句 | 调整花的位置，画风路，播放 | 可编辑和保存的小段音乐 |
| 蒲公英迁徙 | 鼠标指路，声音控制风力，种子落地 | 看得见因果的新花圃 |
| 工作旁的小天气 | 正常打字，停下来，观察低强度变化 | 长时间相处的环境陪伴 |
| 一件物品的另一种生命 | 同时取物品的声音与颜色 | 有现实关联的个人植物 |
| 共同养一瓶天气 | 导出花园片段，朋友接着改变 | 可交换的共同作品 |

每项都应允许用户随时结束，不用排行榜、任务链或数值奖励维持参与。

## 6. 首版范围与优先级

### P0：必须连起来的一条完整体验

1. Windows 桌面边缘花圃：陪伴/造园切换，点击穿透、暂停和退出。
2. 两种植物：铃铛花和蒲公英，可移动和删除。
3. 短时声音采样：先做起音/节奏与音量映射，能生成不同植物参数。
4. 统一风场：鼠标可完整操作；启用麦克风后声音特征控制力度。
5. 花粉传播：种子落入有效土壤，产生可保存的新芽。
6. 键盘雨：主动启用的后台聚合输入，以及安静时的自然回落。
7. 本地状态保存：重开恢复植物、布局、参数和基础设置；默认静音。

演示闭环：**采样种花 → 拨动发声 → 吹起种子 → 落地生长 → 切回工作 → 重开仍在。**

### P1：P0 稳定后，优先选择其中一到两项

- 编辑、播放和保存风路，让布局成为音乐创作。
- 摄像头短时取色，或用图片取色作为替代。
- 微气候瓶导出/导入，不做在线社交后端。
- 增加含羞草、苔藓等一种行为明显不同的植物。

### P2：后续探索，不作为本次交付承诺

- 手势拿取植物与萤火虫。
- 花盆贴附真实应用窗口、两个窗口之间长藤蔓。
- 双屏种子迁移。
- 系统音乐驱动昼夜与花朵；音频来源与权限单独设计。
- 手柄摇杆控制风、扳机控制雨等额外设备映射。

本版不包含：完整三维世界、自动理解任意声音来源、读取打字内容、情绪诊断、强制云端 AI、多人实时同步。之后若希望引入生成式 AI，应先说明它解决哪一个已验证的体验问题。

## 7. 开源借鉴与实现边界

详细出处、核查日期和许可证记录见 [开源交互参考](../research/open-source-interaction-references.md)。

| 来源 | 借鉴什么 | 不能直接推出什么 |
| --- | --- | --- |
| BongoCat | 桌面键鼠反馈、常驻小体积交互 | 不能直接推出我们已经支持所有输入设备和平台 |
| Lively Wallpaper | 桌面融合、互动网页、全屏暂停等运行策略 | 桌面壁纸与窗口上方的覆盖层是不同能力 |
| Patatap | 按键对应声音和动画，快速建立操作手感 | 原有音画素材是否适合直接复用需要逐项检查 |
| WebGL Fluid Simulation | 指针扰动、涡旋、连续变化的视觉反馈 | 流体效果不是现成的植物生态系统 |
| Meyda | 从音频中提取可映射的连续特征 | 不提供可靠的吹气/杯子/纸张语义分类 |
| EZ-Tree | 参数化造型、随机种子、可复现生成 | 是树木生成，不是完整花园和植物生命周期 |
| Tone.js / MediaPipe | 音频调度、手部关键点等支撑能力 | 框架本身不是产品玩法 |

优先学习输入到反馈的结构，使用我们自己的植物造型、声音和交互设计。候选库是否引入，等技术探针结果再确定。

## 8. 从概念走向实现的建议步骤

不预设团队人数、开发总时长或所有成员的技术栈。按可验证产物推进：

### 阶段一：验证真实桌面能力

交付：一个能在 Windows 上运行的空花圃覆盖层。

- 验证透明显示、点击穿透、主动交互模式、跨应用键盘活动汇总。
- 在文本编辑器正常输入，花园收到强度变化，编辑器输入不受影响。
- 检查 100%/150% 显示缩放及任务栏位置；多显示器可先限制为主屏。
- 若只做出了浏览器版本，标记为“交互原型”，不要宣布真实桌面能力通过。
- 首选 Windows 桌面壳 + Web 渲染的探针；Electron 与 Tauri 依据团队熟悉程度、输入能力和分发结果选择。

### 阶段二：打通一朵花的完整因果

交付：声音生成铃铛花，鼠标/声音驱动风，风影响花与种子。

- 统一输入事件，使麦克风和鼠标作用于同一风场。
- 先把两种植物的反应做清楚，限制粒子和植物数量。
- 音频特征必须能校准与降噪；声音过大时反馈饱和。
- 麦克风关闭后，鼠标仍能完成整个闭环。

### 阶段三：成为能留下来的桌面陪伴

交付：状态恢复、键盘雨、安静模式、稳定的演示包。

- 保存/恢复植物与布局，校验版本和参数范围。
- 添加输入节流、动画降级、静音、设备停止与全屏暂停策略。
- 再选择一至两项 P1 交互；无时间则停在完整 P0。

团队可按“桌面与输入”“场景与植物”“音频与反馈”分工，先约定输入事件和花园状态字段；人数不足时按阶段串行完成。这里是分工建议，尚未指派成员。

## 9. 关键边界与退路

| 不确定点 | 本版约束与退路 |
| --- | --- |
| 风扇、空调和说话误触发吹风 | 用户先开启吹风工具、校准、限制强度；保留鼠标风 |
| 自己的音效又被麦克风收进去 | 采样/吹风时压低花园音效，提供静音与耳机演示方案 |
| 后台输入影响隐私或正常工作 | 默认关闭；只聚合强度，立即丢弃键值，不屏蔽原输入 |
| 前端原型无法感知其他程序打字 | 单独完成桌面输入探针；不把浏览器监听冒充后台能力 |
| 叠层抢点击或挡住重要按钮 | 陪伴模式穿透，造园模式明确获得焦点；一键收起 |
| 粒子或植物越来越多 | 植物/种子数量上限、有效土壤范围、粒子寿命与降级画质 |
| 花园长期运行造成打扰 | 动画幅度有上限、默认静音、可暂停，不用突然的强声光 |
| 摄像头不可用或不愿授权 | 手动选色/图片取色；鼠标替代所有关键手势 |
| 开源代码与素材权利不同 | 记录引用位置与许可证；素材独立核查，优先自制 |

## 10. 60–90 秒演示脚本

1. **0–10 秒**：展示屏幕边缘安静的花圃；打开文本编辑器，几次输入带来细雨，原程序正常工作。
2. **10–25 秒**：展开花园，开启短时采样，轻敲杯子三下；三朵铃铛花出现。该桥段需现场先校准；若起音检测不足，改用更稳定的节奏输入。
3. **25–40 秒**：鼠标拨动花，听到合成节奏；移动它们，反馈跟着位置变化。
4. **40–60 秒**：开启吹风，鼠标指向另一块土；蒲公英散出种子，落地长出新芽。
5. **60–75 秒**：关闭麦克风、退出造园；花园收回边缘。
6. **75–90 秒**：关闭重开，植物和布局仍在；有余力再展示取色或风路演奏。

展示时明确哪些反馈来自真实设备，哪些来自鼠标替代；不靠提前录好的视频冒充实时交互。

## 11. 验收标准

以下是未来实现的验收目标，本次只提交计划：

- 新用户不听长讲解，也能完成种花、拨动、传粉三个动作。
- 一次风输入同时影响至少两类对象，种子落地后的变化可保存。
- 在真实文本编辑器输入时有后台键盘雨，输入内容和快捷键不被改变。
- 关闭麦克风后设备释放，花园仍可用鼠标操作；摄像头同理。
- 关闭重开后布局、植物参数与声音参数一致。
- 陪伴模式不抢点击，能立刻暂停/退出。
- 目标测试电脑上，主动交互模式目标至少 30 FPS；连续陪伴运行 15 分钟记录 CPU/GPU/内存与输入影响，不能仅凭一次录屏宣称长期稳定。
- 无需登录或联网也能完成 P0；设备权限拒绝有明确替代路径。

后续讨论优先确认：视觉基调、两种首发植物是否合适、P1 选择风路演奏还是现实取色。确认前不扩成完整游戏、社交平台或大型三维项目。
